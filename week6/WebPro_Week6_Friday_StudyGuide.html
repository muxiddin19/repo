fetch() — how to write it

Here is the exact code that powered the joke demo above. Click Next → to go through each line:

JavaScript — step through it
async function loadJoke() {
  const res  = await fetch('https://official-joke-api.appspot.com/random_joke');
  const data = await res.json();
  document.getElementById('jokeSetup').textContent = data.setup;
  document.getElementById('jokePunch').textContent = data.punchline;
}

What does fetch(url) actually do?

1. It creates an HTTP GET request and sends it to the URL you give it.

2. It immediately returns a Promise — you don't wait, your code keeps going.

3. When the server answers, the Promise "resolves" and you can use the data.

What is a URL? The web address of the data you want. You've typed these into a browser your whole life — https://official-joke-api.appspot.com/random_joke is just a web address that returns data instead of a webpage.

Promise — a ticket for future data

Think of it like this: You order coffee at a café. The barista gives you a paper cup with your name on it (a Promise). You can walk away; you don't get the coffee yet. A few minutes later, either your coffee is ready (fulfilled ✅), or they're out of oat milk (rejected ❌). The cup is the Promise — it represents the coffee you will (or won't) get.

JavaScript — handling a Promise
fetch('https://api.example.com/data')
  .then(response => {
    // runs when fulfilled (data arrived!)
    return response.json();
  })
  .then(data => {
    // runs with the actual JSON data
    console.log(data);
  })
  .catch(error => {
    // runs if rejected (no internet, etc.)
    console.error('Failed:', error);
  });
Note on .then(): You need TWO .then() calls for fetch — one to parse the JSON (which is also a Promise!), and one to use the data. You're waiting for two things: the network response, then the JSON parsing.
4

async / await — the easier way to write it

async/await does exactly the same thing as .then() chains — it's just easier to read. Under the hood, they are identical. Most modern code uses async/await.

Old style .then() chain

fetch('/api/joke')
  .then(res => res.json())
  .then(data => {
    show(data);
  })
  .catch(err => {
    error(err);
  });
⟺

New style async/await

async function getJoke() {
  const res  = await fetch('/api/joke');
  const data = await res.json();
  show(data);
}

The two rules — just two things to remember

Rule 1: Write async before the function name. This tells JS: "this function uses the internet."

Rule 2: Write await before any Promise. This tells JS: "wait here until we hear back, but let the rest of the page keep running."

Think of await like this: You're cooking dinner and put pasta on to boil. You don't stand staring at the pot — you go chop vegetables. await is you saying "I'll come back to this when it's ready." The kitchen (browser) keeps working on other things meanwhile.
JavaScript — step through async/await
async function loadUser() {
  const res  = await fetch('https://jsonplaceholder.typicode.com/users/1');
  const user = await res.json();
  console.log('Name:', user.name);   // → "Leanne Graham"
  console.log('Email:', user.email);  // → "Sincere@april.biz"
}

What can go wrong? — Error handling

The sneaky surprise: 404 does NOT throw an error!

Most beginners expect that if the server says "Not Found" (404), the fetch automatically fails. It does not. fetch() only rejects (throws) if there is no internet at all. A 404 from the server still "succeeds" from fetch()'s point of view.

This is a famous "gotcha" that confuses even experienced developers. You must always check response.ok yourself.

JavaScript — the correct pattern
async function loadData(url) {
  try {

    const res = await fetch(url);

    // ← YOU must check this. fetch() won't do it for you!
    if (!res.ok) throw new Error(`HTTP error: ${res.status}`);

    const data = await res.json();
    showData(data);       // happy path

  } catch (err) {
    showError(err.message); // any error lands here

  } finally {
    hideSpinner();         // ALWAYS runs (success or fail)
  }
}

What does try / catch / finally mean?

try — "run this code, but be careful."

catch — "if ANYTHING goes wrong in try, do this instead."

finally — "do this no matter what happened. Always." (Great for hiding loading spinners!)

Quick reference — when does fetch reject vs. when must you check?
❌ No internet → fetch() auto-throws → goes to catch
⚠️ Server says 404 → fetch() resolves → you must check !res.ok
⚠️ Server says 500 → fetch() resolves → you must check !res.ok

Step 5 — Add error handling (the professional finish) ▸

Wrap it in try/catch/finally so it never breaks silently.

JavaScript — complete version
async function loadJoke() {
  const status = document.getElementById('status');
  status.textContent = 'Loading…';

  try {
    const res  = await fetch('https://official-joke-api.appspot.com/random_joke');
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const data = await res.json();

    document.getElementById('joke-area').innerHTML =
      `<p><strong>${data.setup}</strong></p>
       <p>${data.punchline}</p>`;

  } catch (err) {
    status.textContent = 'Error: ' + err.message;

  } finally {
    if (!status.textContent.startsWith('Error'))
      status.textContent = '';
  }
}

Quick Quiz — Check yourself

1. What does fetch(url) return right away?

✅ B — A Promise. fetch() returns a Promise immediately so your code can keep running while the network request is happening in the background.

2. The server returns HTTP 404. What does fetch() do?

✅ C. The big gotcha! fetch() only rejects when there is NO internet. A 404 or 500 from the server still resolves the Promise. Always write if (!res.ok) throw new Error(...).

3. Which keyword goes BEFORE the function declaration to allow await inside?

✅ C — async. async function myFn() { ... } — the async keyword before the function name enables await inside that function.

4. Which block runs whether fetch() succeeds OR fails?

✅ C — finally. The finally block always runs: after try succeeds, or after catch handles an error. Perfect for hiding loading spinners.

5. You have a .then() chain and forget to write return in the first .then(). What happens?

✅ B — undefined. Each .then() passes its return value to the next .then(). Forgetting return means the next step gets undefined — a silent bug!

Summary — the 6 things to remember

fetch(url)
Sends an HTTP GET request. Returns a Promise immediately — page stays interactive.
res.json()
Parses the response body as JSON. Also returns a Promise — await it too.
res.ok
true for HTTP 200-299. fetch() does NOT auto-reject on 404/500 — check this yourself.
async function
Marks a function as one that uses the internet. Enables await inside it.
await
Pauses THIS function (not the page) until the Promise resolves. Other JS keeps running.
finally
Always runs — after try OR after catch. Use it to hide spinners and reset buttons.
JavaScript — the pattern to memorise
async function loadData(url) {
  showSpinner();          // show loading before anything
  try {
    const res  = await fetch(url);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const data = await res.json();
    render(data);           // success! show the data
  } catch (err) {
    showError(err.message); // something went wrong
  } finally {
    hideSpinner();          // always hide loading
  }
}
