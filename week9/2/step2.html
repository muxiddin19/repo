Initialize Your Local Repository

Turn your Book Search project folder into a Git repository, stage all files, and make your first commit.

A Open a Terminal in Your Project Folder

You need a terminal (Command Prompt, PowerShell, or Terminal) pointed at the folder where your index.html lives.

1
Windows: Open File Explorer, navigate to your project folder, click the address bar, type cmd, and press Enter. A Command Prompt opens at that location.
2
Mac: Right-click the project folder in Finder → New Terminal at Folder. Or use cd to navigate there.
3
Confirm you are in the right place — list the files:
terminal # Windows $ dir index.html style.css script.js # Mac / Linux $ ls index.html style.css script.js
index.html must be visible in this listing. If not, use cd foldername to go deeper into the correct directory.

B Initialize the Git Repository

This creates a hidden .git folder inside your project that Git uses to track all changes.

terminal $ git init Initialized empty Git repository in /path/to/your/project/.git/
This only needs to be done once per project. The .git folder stores all of the version history — never delete it.

C Stage All Your Files

Staging means telling Git which files to include in the next commit. The . means "everything in this folder".

terminal $ git add .

Check what is staged:

terminal $ git status On branch master Changes to be committed: new file: index.html new file: style.css new file: script.js

What these status colors mean:

new file:   index.html — staged and ready to commit
modified:   index.html — changed but NOT yet staged (run git add again)
?? index.html            — untracked (not staged yet)

D Make Your First Commit

A commit is a permanent snapshot of your staged files. The -m flag lets you write the message inline.

terminal $ git commit -m "first commit: add Book Search App" [master (root-commit) a1b2c3d] first commit: add Book Search App 3 files changed, 87 insertions(+) create mode 100644 index.html create mode 100644 script.js create mode 100644 style.css

The three-step Git workflow (you will repeat this every time):

git add .Stage changes — tell Git what to include
git commit -m "..."Snapshot the staged state with a message
git pushUpload commits to GitHub (we do this in Step 4)
Write good commit messages. Describe what changed and why — "fixed search button" is better than "update". Your future self will thank you.
