Connect Local Repo to GitHub & Push

Link your local Git repository to the GitHub remote you created, then upload your commits to the cloud.

A Add the Remote URL

A "remote" is a named shortcut pointing to a URL on GitHub. By convention the default remote is named origin.

Replace <URL> with the HTTPS URL you copied at the end of Step 3 — it ends in .git.

terminal $ git remote add origin https://github.com/your-username/webpro-booksearch.git

Verify the remote was added:

terminal $ git remote -v origin https://github.com/your-username/webpro-booksearch.git (fetch) origin https://github.com/your-username/webpro-booksearch.git (push)

Command breakdown:

git remote addRegister a new remote connection
originThe name we give this remote (convention — could be anything)
https://...The HTTPS address of the repository on GitHub

B Rename Your Branch to "main"

Older versions of Git name the default branch master. GitHub and GitHub Pages expect main. This one command renames it.

terminal $ git branch -M main
If git init already created a main branch (Git 2.28+), this command does nothing harmful — it just confirms the name.

C Push Your Commits to GitHub

This uploads your local commit history to the origin remote and sets main as the default tracking branch.

terminal $ git push -u origin main

Git will ask for your GitHub credentials. Follow the prompts:

1
A browser window opens asking you to sign in to GitHub.
↓
2
Click Authorize git-credential-manager (or enter your username and a Personal Access Token).
↓
3
Return to the terminal. The push output appears.

Expected output after successful push:

terminal Enumerating objects: 5, done. Counting objects: 100% (5/5), done. Writing objects: 100% (5/5), 2.31 KiB | 2.31 MiB/s, done. Total 5 (delta 0), reused 0 (delta 0), pack-reused 0 To https://github.com/your-username/webpro-booksearch.git * [new branch] main -> main Branch 'main' set up to track remote branch 'main' from 'origin'.
Success! Open your repository on GitHub — you should see your index.html and other files listed there.

Future pushes are shorter:

git push -u origin mainFirst push: -u sets the default upstream. Required once.
git pushAll future pushes on this branch — no flags needed.

? Authentication Troubleshooting

If the browser window does not open (common on some Linux/lab setups), you may need a Personal Access Token (PAT) instead of your password.

1
Go to GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token.
2
Give it a name. Set repo scope. Set expiration to 90 days. Click Generate token.
3
Copy the token immediately (it is shown only once).
4
When the terminal asks for a password, paste the token — not your GitHub login password.
On Windows with Git Credential Manager installed (the default), credentials are saved in Windows Credential Manager after the first successful push — you will not be asked again.
