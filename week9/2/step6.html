Check that your live site works correctly, and fix the most common deployment problems.

✓ Verify Your Live Site

Before calling it done, check that your site works correctly for a real visitor.

🕵
Test in an incognito / private window
Press Ctrl+Shift+N (Chrome/Edge) or Ctrl+Shift+P (Firefox) to open an incognito window. Open your GitHub Pages URL there. This ensures you are not seeing a cached version from your development work.
📱
Test on a phone
Open your GitHub Pages URL on your smartphone. If your CSS uses relative units and flexbox, the layout should adapt. A live mobile test catches issues that desktop DevTools emulation misses.
🔍
Search for a book
Type a query ("dune", "harry potter") and submit the form. The Open Library API is a public HTTPS endpoint — it should work from any hosted domain. If results appear, your full stack is working.
🚨
Check DevTools Console for errors
Press F12 → Console tab. A working page should have zero red errors. Warnings (yellow) are usually fine. A red error often points directly to the broken file or line.

! Common Issues & Fixes

The site shows a 404 "File not found" error
MOST COMMON
Possible cause 1: Pages is still building. Wait 60–90 seconds and refresh.
Possible cause 2: Your index.html is missing from the root of the repository. GitHub Pages specifically looks for a file named index.html in the root (or /docs folder if you chose that).
Fix
1
Check your repository on GitHub — is index.html listed in the file browser? If not, your project folder may have a different file name or be inside a subfolder.
2
If index.html is inside a folder, go to Step 5 and change the folder setting to match that subfolder, OR move the file to the root and push again.
Pages is configured but the site is still not live
BRANCH ISSUE
Cause: Pages is set to the main branch but your commits are on master (or vice versa).
Fix
1
Check the branch name in your local terminal:
git branch * main
2
If the branch is master, rename it: git branch -M main then git push -u origin main.
3
In Settings → Pages, confirm the branch is set to main.
Page loads but CSS/images are missing or broken
PATH ISSUE
Cause: You used an absolute path like /style.css (starts with /). On GitHub Pages the base URL is /webpro-booksearch/, so /style.css resolves to the wrong location.
Fix — use relative paths everywhere
<!-- WRONG — absolute path --> <link rel="stylesheet" href="/style.css"> <!-- CORRECT — relative path --> <link rel="stylesheet" href="style.css"> <link rel="stylesheet" href="./style.css">
1
Open index.html locally, fix all href and src values that start with /.
2
Save, then run: git add . → git commit -m "fix relative paths" → git push. Wait 60 seconds.
Book search returns no results or a network error
API / CORS
Cause: Open Library is an external API. Open DevTools → Network tab and look for a red request. Common problems: wrong URL in the fetch call, or a mixed-content error (your code uses http:// instead of https://).
Fix
1
Make sure your fetch URL starts with https:// — GitHub Pages is served over HTTPS, so any http:// requests are blocked by the browser.
// WRONG fetch('http://openlibrary.org/search.json?q=...') // CORRECT fetch('https://openlibrary.org/search.json?q=...')
Works on Windows/Mac locally but 404 on GitHub Pages
CASE SENSITIVITY
Cause: Windows and macOS file systems are case-insensitive. GitHub Pages runs on Linux, which IS case-sensitive. A file named Style.css is NOT the same as style.css on Linux.
Fix
1
Use all-lowercase filenames: style.css, script.js, index.html.
2
Make sure all href and src attributes match the exact filename case.

↻ Updating Your Site After Changes

Any time you edit your project and want the live site to update, run these three commands:

terminal # 1. Stage your changes $ git add . # 2. Commit with a descriptive message $ git commit -m "improve search result cards" # 3. Push to GitHub — Pages rebuilds automatically $ git push
Wait about 60 seconds after pushing, then hard-refresh your browser (Ctrl+Shift+R / Cmd+Shift+R) to clear the cache and see the updated site.
