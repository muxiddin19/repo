Image Performance — Lazy Loading & Dimensions

The broken page loads all five images immediately, even those below the fold. Add loading="lazy" and explicit width/height to fix bandwidth waste and layout shift.

1 2 3 4 5 6 7

What you are fixing

The five images have no width or height attributes. The browser downloads them all the moment the page loads, even the ones at the bottom. As each image arrives, the browser reflows the page — text and buttons jump around. This is called Cumulative Layout Shift (CLS) and it directly reduces the Lighthouse Performance score. Adding loading="lazy" defers below-fold images until the user scrolls near them.

What these optimizations fix
📸
Cumulative Layout Shift (CLS)
Without width/height, the browser doesn't know how much space to reserve. Content jumps as images load.
↑ width + height eliminates CLS
⏱
Largest Contentful Paint (LCP)
All images compete for bandwidth at once. The hero image (above fold) loads slower than needed.
↑ lazy loading frees bandwidth for LCP
📶
Total Blocking Time (TBT)
Large images on slow connections delay time-to-interactive. Lazy loading reduces initial payload.
↑ reduces initial page weight
📱
Mobile data usage
A user who never scrolls to the bottom still downloads all images in the broken version.
↑ lazy loading saves ~3 MB on mobile

Bonus — modern image formats (WebP / AVIF)

WebP is 25–35% smaller than JPEG at the same quality

Real-world projects serve images in WebP (or AVIF). You can do this with the <picture> element and a JPEG fallback:

<picture>
  <source srcset="poster-movie1.webp" type="image/webp">
  <img src="poster-movie1.jpg"
       alt="Movie poster for Echoes of Tomorrow"
       width="400" height="560"
       loading="lazy">
</picture>

The browser picks WebP if it can; older browsers fall back to JPEG. In this lab we use placeholder URLs, so we cannot switch formats — but remember this pattern for real projects.

Never add loading="lazy" to above-fold images. The first image the user sees (the LCP element) must start loading immediately. Adding lazy to it delays the very metric Lighthouse is measuring. Rule: lazy-load the second image and below, or anything not visible on a typical screen without scrolling.
