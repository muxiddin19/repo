Form Accessibility — Labels & Error Messages

Three inputs have no <label>. Add labels and wire up error messages with aria-describedby so screen readers announce them automatically.

1 2 3 4 5 6 7

What you are fixing

The broken page has a search input and two newsletter inputs (name and email) with no <label> elements. The placeholder text disappears as soon as the user starts typing — leaving them with no hint about what to enter. A screen reader user hears "edit text" with no further context. This step also adds an error message connected by aria-describedby so it is read aloud automatically.

<label for="nl-name">Your name</label>
<input type="text" id="nl-name">

<label for="nl-email">Email</label>
<input type="email" id="nl-email"
  aria-describedby="email-err"
  aria-invalid="false">
<span id="email-err"
  role="alert" style="display:none">
  Please enter a valid email.
</span>
Why this matters

The label is the input's name — always visible, always connected

A <label for="id"> paired with an id on the input does three things: it gives screen readers a name to announce, it makes the label clickable to focus the input (helpful on mobile), and it stays visible after the user starts typing (unlike a placeholder, which vanishes).

Placeholder is not a label. WCAG 1.3.5 requires inputs to be programmatically determinable. A placeholder only appears before the user types. It also commonly has low contrast (fails Step 4). Never rely on placeholder alone.

aria-describedby links extra information to an input

  • Give the error message span an id: e.g., id="email-err"
  • Add aria-describedby="email-err" to the input
  • When the screen reader focuses the input, it reads the label first, then the describedby text
  • Add role="alert" to the error span so it is also announced immediately when it becomes visible
  • Toggle aria-invalid="true" on the input when validation fails
Visually hiding a label: Sometimes designers don't want a visible label (e.g., a search bar in a nav). In that case, use a CSS class instead of display:none — hidden labels are not announced. A common visually-hidden class: .sr-only { position:absolute; width:1px; height:1px; overflow:hidden; clip:rect(0,0,0,0); white-space:nowrap; }
