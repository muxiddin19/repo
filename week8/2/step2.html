Buttons & Descriptive Links

Replace every <div onclick> with a real <button>. Rename every "click here" link to say exactly where it goes.

1 2 3 4 5 6 7

What you are fixing

The search button, all four movie card buttons, and the newsletter submit are <div> elements with an onclick attribute. A keyboard-only user can never reach them — pressing Tab skips all divs. A screen reader user hears nothing useful. The three "Click here" links are meaningless when a screen reader reads out all links on the page.

Why this matters

Buttons vs. divs: the browser gives <button> superpowers for free

A native <button> automatically:

  • Receives keyboard focus when users press Tab
  • Activates with Enter or Space
  • Is announced by screen readers as a "button" with its label
  • Shows a visible focus ring so keyboard users know where they are
  • Respects disabled state automatically

You could add all of this to a <div> with role="button", tabindex="0", and JavaScript keyboard handlers — but why? The browser already does it for <button>.

Link text rule: Every <a> tag's text must make sense as a standalone phrase. Screen readers offer a "Links" menu — imagine 30 links all reading "Click here". Always write where the link goes, not how to activate it.

Button vs. link — which to use? Use <button> for actions that happen on the current page (submit a form, open a dialog, toggle something). Use <a href> for navigation — moving to a different page or section. Never use a link to submit a form, and never use a button to navigate to a new URL.
