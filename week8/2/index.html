WEEK 7 · ACCESSIBILITY & PERFORMANCE · LAB

Fix the Broken Website

You have inherited a client's movie review site. It works — barely — but it fails every accessibility audit and loads too slowly. Your job is to fix it, step by step.

Monday: Web Accessibility (Steps 1–5) Friday: Performance Optimization (Steps 6–7) ~60 min total

What you will fix today

1Replace every <div> with proper semantic HTML5 elements — <header>, <nav>, <main>, <article>, <footer>
2Replace fake <div onclick> buttons with real <button> elements that keyboard and screen reader users can reach
3Add meaningful alt text to every content image; use alt="" for decorative ones so screen readers skip them
4Fix five color contrast failures using browser DevTools — raise every ratio to at least 4.5:1
5Connect every form input to a <label for="id">; add aria-describedby so error messages are announced
6Add loading="lazy" plus explicit width and height to below-fold images to prevent layout shift (CLS)
7Move all <script> tags to the end of <body> and add defer so they never block HTML parsing

All bugs in broken.html at a glance

A1Entire page uses <div> wrappers — no semantic landmarks for screen readers
A2Search bar, movie card buttons, and newsletter submit use <div onclick> — not keyboard-operable
A3Four images: blank alt="" on content image, missing alt, alt="img", and filename as alt
A4Five color pairs fail WCAG AA — worst is #aaa on #eee (ratio 1.6:1 vs. required 4.5:1)
A5Search input and both newsletter inputs have no <label>
A6Three links read "Click here" — meaningless when a screen reader lists all links
P1No width/height on images; below-fold images load eagerly (wastes bandwidth)
P2Two <script> tags in <head> with no defer — block HTML parsing and delay first paint
