This guide covers every topic tested in the Week 2 quiz. Each topic includes theory, a code example you can preview, and key points. After the 25 topics, practice your skills in the exercises section — you write HTML in the editor and see the result instantly.

01

What is HTML?

Q1

HTML stands for HyperText Markup Language. Each word tells you something: HyperText means text with links that connect to other documents; Markup means the text is annotated with tags that describe its structure; Language means it follows defined rules a browser can interpret.

HTML is not a programming language — it cannot perform calculations or make decisions. It is a markup language that describes structure: "this is a heading," "this is a paragraph," "this is a link." CSS handles visual design and JavaScript handles behaviour. In this course you learn all three, but HTML must come first — nothing else can exist without it.

Every website you have ever visited began as an HTML file. You can see any page's HTML by pressing Ctrl+U in Chrome.

HTML
<!-- HTML describes structure, not appearance --> <!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>My First Page</title> </head> <body> <h1>Hello, world!</h1> <p>This paragraph is written in HTML.</p> <p>CSS would style it. JavaScript would animate it.</p> </body> </html>

Key Points

  • HTML = HyperText Markup Language — structure only.
  • Not a programming language — it cannot calculate or decide.
  • Every web page starts as an HTML file.
  • HTML5 is the current standard (since 2014).
02

DOCTYPE Declaration

Q2

The <!DOCTYPE html> declaration must be the very first line of every HTML file — even before the <html> tag. It is not an HTML tag; it is an instruction to the browser's parser that tells it which version of HTML the file uses.

Without a DOCTYPE, browsers enter "quirks mode" — an old compatibility mode that renders pages differently across browsers, making consistent design nearly impossible. The HTML5 DOCTYPE (<!DOCTYPE html>) triggers standards mode, where all modern browsers behave consistently. Notice it is much shorter than the old HTML4 doctype (which was over 70 characters).

HTML
<!-- HTML5 DOCTYPE — always use this exact string --> <!DOCTYPE html> <html lang="en"> <head> <title>Correct DOCTYPE</title> </head> <body> <p>This page renders in standards mode.</p> </body> </html> <!-- Old HTML4 DOCTYPE (for reference only — never use this) --> <!-- <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd"> -->

Key Points

  • Must be the very first line — before even <html>.
  • NOT a tag — it is a parser instruction, no closing version.
  • Triggers standards mode for consistent cross-browser rendering.
  • HTML5 DOCTYPE is just <!DOCTYPE html> — simple and short.
03

The <body> Element

Q3

The <body> element is the container for everything the user sees on the page. All text, images, headings, links, forms, and media must be placed inside the body. There is exactly one body element per HTML document.

The <head> section (its sibling) holds invisible metadata — the browser reads it but the user never sees it directly. A common beginner mistake is placing visible text in the head or forgetting to close the body properly. The browser is forgiving about missing closing tags, but always close them explicitly for clean, valid HTML.

HTML
<!DOCTYPE html> <html lang="en"> <head> <!-- INVISIBLE — user never sees this section --> <meta charset="UTF-8"> <title>Browser Tab Text</title> </head> <body> <!-- VISIBLE — everything the user sees goes here --> <h1>This heading is visible</h1> <p>This paragraph is visible.</p> <img src="photo.jpg" alt="A photo"> <a href="about.html">This link is visible</a> </body> </html>

Key Points

  • body = everything visible to the user.
  • head = invisible metadata (title, charset, CSS links).
  • One body element per page.
  • Never place text content inside <head>.
04

Headings h1–h6

Q4, Q11

HTML provides six heading levels, <h1> through <h6>. h1 is the largest and most important; h6 is the smallest. Headings serve both visual and semantic purposes — they communicate the structure of your content to browsers, search engines, and screen readers.

Two critical rules: First, use exactly one <h1> per page — it signals the main topic to search engines and affects your Google ranking. Second, never skip heading levels (do not jump from h1 to h3) — screen readers allow users to navigate by heading, and a broken hierarchy confuses them. Change visual size with CSS, not by choosing a lower heading level.

HTML
<!DOCTYPE html> <html lang="en"> <head><meta charset="UTF-8"><title>Recipe</title></head> <body> <h1>Korean Kimchi Recipe</h1> <!-- ONE per page --> <h2>Ingredients</h2> <h3>Vegetables</h3> <h3>Seasoning</h3> <h2>Instructions</h2> <h3>Step 1: Prepare the cabbage</h3> <h3>Step 2: Make the paste</h3> <h2>Storage Tips</h2> <!-- Wrong — skipping h2 goes directly to h3: --> <!-- <h1>Title</h1><h3>Section</h3> ← BAD! --> </body> </html>

Key Points

  • h1 = once per page (the main topic — affects SEO).
  • Never skip levels: h1 → h2 → h3 in order.
  • Headings communicate semantic hierarchy, not just size.
  • Use CSS to change visual size — never choose headings for their size.
05

The <head> Section

Q8

The <head> element is invisible to users but essential for browsers and search engines. It holds metadata — information about the page rather than content for the page. The four most important things you put in the head are: the character encoding (meta charset), the viewport setting for mobile, the page title, and links to CSS stylesheets.

Nothing inside <head> is rendered on the page. If you accidentally place text or images inside head, they will not appear (or will cause broken rendering). Think of head as the "settings panel" for the page.

HTML
<head> <!-- 1. Character encoding — always first --> <meta charset="UTF-8"> <!-- 2. Viewport — makes the page work on phones --> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <!-- 3. Page title — browser tab + Google search result --> <title>Kim Jisoo — Web Portfolio</title> <!-- 4. Connect CSS stylesheet --> <link rel="stylesheet" href="style.css"> <!-- 5. Optional: description for Google snippet --> <meta name="description" content="Portfolio of Kim Jisoo, Web Programming student."> </head>

Key Points

  • head = invisible metadata — nothing in it appears on the page.
  • Always include: charset, viewport, title.
  • The browser reads head; the user reads body.
  • CSS links go in head so styles load before the page renders.

meta charset UTF-8

Q18

The <meta charset="UTF-8"> tag tells the browser how to decode the bytes in your HTML file. UTF-8 is a character encoding that supports over 1 million characters, including every human language: Korean (한글), Japanese, Chinese, Arabic, Greek, and emoji.

Without this tag, Korean text displays as garbage symbols (e.g., Ã©â€˜Œ Ã©ˆ® instead of 학번). It should be the first tag inside <head> so the browser decodes all subsequent content correctly. UTF-8 is the universal standard — there is no reason to use any other encoding for new web pages.

HTML
<head> <!-- Always the FIRST tag in head --> <meta charset="UTF-8"> <title>Page with Korean text</title> </head> <body> <!-- Korean displays correctly with UTF-8 --> <p>학번: 202438037</p> <p>이름: 김지수</p> <p>과목: 웹프로그래밍</p> <!-- Without charset, Korean becomes garbage: --> <!-- Ã©â€˜Œ ÃˆÂ£ 202438037 --> </body>

Key Points

  • UTF-8 supports ALL human languages including Korean (한글).
  • Must be the first tag inside <head>.
  • Without it: Korean and special characters display as garbage.
  • Always use charset='UTF-8' — no exceptions.
07

The <title> Element

Q20

The <title> element inside <head> sets the text shown in the browser tab. It is also the headline Google shows in search results — the clickable blue link. A good title is descriptive (50–60 characters), unique per page, and tells the user exactly what the page contains.

The title does NOT appear on the page itself — do not confuse it with an <h1> heading. Bad titles: "Home", "Page 1", "Untitled". Good titles: "Kim Jisoo — Web Programming Portfolio · Gachon University". Every page on a website should have a different title.

HTML
<head> <meta charset="UTF-8"> <!-- Bad titles — avoid these --> <!-- <title>Home</title> too generic --> <!-- <title>Page</title> meaningless --> <!-- Good title: descriptive + unique --> <title>Kim Jisoo — Web Programming Portfolio</title> </head> <!-- The title ONLY shows in: 1. The browser tab 2. Google search results (the blue link) 3. Bookmarks / favourites It does NOT appear anywhere on the page body. -->

Key Points

  • Title appears in browser tab and Google search results — NOT on the page.
  • 50–60 characters ideal for Google.
  • Each page on a site should have a unique title.
  • Missing or generic title hurts SEO significantly.
08

The lang Attribute

Q23

The lang attribute on the <html> element declares the page's primary language. Use "en" for English, "ko" for Korean, "zh" for Chinese, etc. Screen readers use lang to select the correct pronunciation voice; spell-checkers use it to apply the right dictionary; translation tools use it to offer "Translate this page."

A missing lang attribute is a WCAG Level A accessibility failure — the most serious type of accessibility violation. Always set it. You can also add lang to individual elements to mark text in a different language within an otherwise English page.

HTML
<!-- English page --> <html lang="en"> <!-- Korean page --> <html lang="ko"> <!-- Page is English but has Korean student ID --> <html lang="en"> <body> <p>Your student ID is: <span lang="ko">학번 202438037</span> </p> </body>

Key Points

  • lang on <html> declares the page's primary language.
  • 'en'=English, 'ko'=Korean. Always include it.
  • Used by screen readers, spell-checkers, and translation tools.
  • Missing lang is a WCAG accessibility violation.
09

Paragraphs & Block Elements

Q7

The <p> element represents a paragraph of text. It is a block-level element — it always starts on a new line and the browser adds a small margin above and below it automatically. You do not need <br> tags to create spacing between paragraphs; the browser handles that.

An important rule: whitespace in HTML source code is collapsed. If you write 10 blank lines or 20 spaces in a row, the browser renders it as a single space. Line breaks in your code are ignored — a paragraph only ends when you write the closing </p> tag. A <p> can contain inline elements (strong, em, a, span) but never another block element like <div> or another <p>.

HTML
<body> <p>This is the first paragraph. Extra spaces and line breaks in the source are all collapsed to one space.</p> <p>This is the second paragraph — the browser adds margin between paragraphs automatically.</p> <p>Inline elements are fine inside a paragraph: <strong>bold text</strong>, <em>italic text</em>, and <a href="#">links</a> all work here.</p> <!-- Wrong — block element inside p --> <!-- <p>Text <div>oops</div> more text</p> ← BAD! --> </body>

Key Points

  • p is block-level — always starts a new line.
  • Whitespace in HTML source collapses to a single space.
  • Browser adds margin between paragraphs automatically.
  • p can contain inline elements but NOT block elements.
10

Inline Elements & <span>

Q19

Inline elements flow within the text — they do not start a new line and only occupy as much width as their content needs. <span> is the generic inline container: it has no visual effect by default but can be targeted by CSS (with a class or id) to apply colour, font, or any other style.

Other common inline elements: <a> (links), <strong> (bold), <em> (italic), <img> (images), <code> (code snippets). The rule: inline elements should contain only text or other inline elements — never block elements like <p> or <div>.

HTML
<body> <!-- Inline elements flow on the same line --> <p> Normal text, <strong>bold text</strong>, <em>italic text</em>, <a href="#">a link</a>, and <span class="highlight">highlighted text</span> all sit on ONE line. </p> <!-- span is invisible by default — CSS gives it style --> <style> .highlight { background: yellow; color: black; padding: 2px 4px; } </style> <!-- Wrong: block element inside inline --> <!-- <span><p>text</p></span> ← BAD! --> </body>

Key Points

  • Inline elements flow with text — no new line, width = content width.
  • span = generic inline container (no default style).
  • Inline elements contain only text or other inline elements.
  • CSS + class/id gives span its styling power.
11

<strong> — Bold & Important

Q15

<strong> makes text bold AND signals that the content is semantically important. Screen readers may read strong text with added emphasis, and search engines may treat it as significant. Use strong for warnings, key terms, and critical information.

<b> also renders bold but has no semantic meaning — it is purely presentational. Prefer strong in almost every case. If you just want bold text for stylistic reasons with no implied importance, use <b> or CSS font-weight: bold.

HTML
<body> <!-- strong = bold + semantically important --> <p>Quiz deadline: <strong>Friday 09:00</strong>. Submissions after this time receive zero marks.</p> <p>Warning: <strong>never submit without the DOCTYPE.</strong></p> <!-- b = bold only, no semantic weight --> <p>The <b>h1</b> element is discussed in topic 4.</p> <!-- (here b is used for a visual style, not importance) --> <!-- both render identically in most browsers --> <!-- difference is MEANING, not appearance --> </body>

Key Points

  • strong = bold + semantically important (preferred).
  • b = bold only, no semantic meaning.
  • Screen readers may stress-read <strong> text.
  • Use strong for warnings, key terms, critical information.
12

<em> — Italic & Emphasis

Q16

<em> (emphasis) renders text in italic and indicates that the text should be spoken with stress. The stressed word changes the meaning of the sentence: "I never said she stole it" vs "I never said she stole it." Screen readers adjust their intonation for em.

<i> also renders italic but carries no semantic meaning. Use <i> for technical terms, foreign words, or purely stylistic italic. Use <em> when the emphasis actually changes or strengthens the meaning. For code variable names or technical identifiers, use the <code> element instead.

HTML
<body> <!-- em changes meaning based on which word is stressed --> <p>You <em>must</em> submit by Friday.</p> <p><em>You</em> must submit by Friday. (not someone else)</p> <!-- i for terms/titles, no semantic emphasis --> <p>The element <i>em</i> stands for emphasis.</p> <p>In Korean, <i>학번</i> means student ID number.</p> <!-- code for technical/code terms --> <p>Use the <code>font-size</code> property to change text size.</p> </body>

Key Points

  • em = italic + semantically emphasised (meaning changes).
  • i = italic only, no semantic weight.
  • Screen readers adjust intonation for <em>.
  • For code/technical terms: use <code>, not <em>.
13

Void Elements & <br>

Q9, Q17

Most HTML elements have both an opening and closing tag. Void elements are the exceptions — they have no content and no closing tag. Examples: <br>, <img>, <input>, <meta>, <link>, <hr>. In HTML5, the self-closing slash is optional: <br> and <br/> are both valid; </br> is wrong.

<br> creates a line break within a block of text. Its legitimate use cases are narrow: poetry, postal addresses, song lyrics — situations where the line breaks are part of the content. Do not use <br><br> to create spacing between sections — use CSS margin instead.

HTML
<body> <!-- Legitimate use of br: a mailing address --> <address> Prof. Kim Jisoo<br> Department of Computer Science<br> Gachon University, Seongnam<br> Gyeonggi-do, South Korea </address> <!-- Void elements — no closing tag needed --> <img src="photo.jpg" alt="Profile photo"> <meta charset="UTF-8"> <input type="text" placeholder="Name"> <hr> <!-- horizontal rule --> <!-- Wrong uses --> <!-- </br> ← invalid closing tag for void element --> <!-- <br><br><br><br> to create space ← use CSS margin instead --> </body>

Key Points

  • Void elements have no closing tag: <img>, <br>, <input>, <meta>, <hr>.
  • <br> = line break within text (poetry/addresses).
  • Don't use <br><br> for spacing — use CSS margin.
  • <br> and <br/> both valid in HTML5; </br> is wrong.
14

Links: the <a> Tag & href

Q5

The <a> (anchor) element creates hyperlinks — Tim Berners-Lee's invention that defines the World Wide Web. The href (HyperText REFerence) attribute specifies the destination. Without href, the element renders but has no link behaviour.

There are five types of href values: (1) absolute URLs (https://...) for external sites; (2) relative URLs (about.html) for pages on the same server; (3) fragment links (#section-id) to jump within the same page; (4) mailto: to open an email client; (5) tel: for phone links on mobile. Always write descriptive link text — "Learn more about HTML" not just "Click here."

HTML
<body> <!-- 1. External link (absolute URL) --> <a href="https://www.w3schools.com">W3Schools HTML Tutorial</a> <!-- 2. Internal link (relative path) --> <a href="about.html">About Me</a> <a href="projects/portfolio.html">My Projects</a> <!-- 3. Fragment link — jumps to id="contact" on this page --> <a href="#contact">Jump to Contact Section</a> ... <section id="contact"> <h2>Contact</h2> </section> <!-- 4. Email link --> <a href="mailto:student@gachon.ac.kr">Email me</a> <!-- 5. Phone link (tappable on mobile) --> <a href="tel:+821012345678">Call: +82 10-1234-5678</a> </body>

Key Points

  • href is required for the link to work.
  • Absolute URL (https://): for external sites.
  • Relative URL (page.html): for your own pages.
  • Descriptive link text helps accessibility and SEO.
15

target="_blank"

Q10

The target attribute controls where the linked page opens. target="_blank" opens the link in a new browser tab (or window, depending on browser/user settings). Use it for external links so users do not leave your site.

Security note: always add rel="noopener noreferrer" when using target="_blank". Without it, the opened page can access your page through window.opener — a security vulnerability. Modern browsers auto-add this protection, but explicitly writing it is best practice and shows code quality awareness.

HTML
<body> <!-- Internal links: same tab (no target) --> <a href="about.html">About Me</a> <a href="projects.html">My Projects</a> <!-- External links: new tab + security attribute --> <a href="https://github.com" target="_blank" rel="noopener noreferrer"> My GitHub Profile </a> <a href="https://www.gachon.ac.kr" target="_blank" rel="noopener noreferrer"> Gachon University </a> </body>

Key Points

  • target='_blank' opens the link in a new tab.
  • Always pair with rel='noopener noreferrer' for security.
  • Use for external links — keep internal links in the same tab.
  • Users can always right-click → open in new tab if preferred.
16

Unordered Lists <ul>

Q12

The <ul> element creates an unordered (bulleted) list. Each item inside a ul must be an <li> element. Browsers render bullet points by default; CSS can change or remove them (list-style: none). The ul element is block-level and adds indentation.

Use ul when the items have no meaningful order — a shopping list, a list of features, navigation links. Navigation menus are almost always built as ul lists (with CSS removing the bullets and making them horizontal). Only direct children of ul should be li elements — never place <p> or <div> directly inside ul.

HTML
<body> <!-- Basic unordered list --> <h2>My Skills</h2> <ul> <li>HTML — page structure</li> <li>CSS — visual design</li> <li>JavaScript — interactive behaviour</li> <li>PHP — server-side logic</li> </ul> <!-- Navigation (common pattern) --> <nav> <ul> <li><a href="/">Home</a></li> <li><a href="/about">About</a></li> <li><a href="/contact">Contact</a></li> </ul> </nav> <!-- CSS would remove bullets and make items horizontal --> </body>

Key Points

  • ul = unordered list — items have no meaningful order.
  • Direct children must be <li> elements only.
  • Browser renders bullet points by default (CSS can remove them).
  • Navigation menus are typically <nav><ul><li><a> structures.
17

Ordered Lists <ol>

Q24

The <ol> element creates an ordered (numbered) list. The browser automatically generates the numbers — you do not write them in the HTML. By default, items are numbered 1, 2, 3… You can customise with attributes: type="A" (A, B, C), type="a" (a, b, c), type="I" (Roman numerals), and start="5" to begin at a different number.

Use ol when the sequence matters: installation steps, recipe instructions, top-10 rankings, legal clauses. If the order does not matter, use ul. Like ul, only <li> elements should be direct children of ol.

HTML
<body> <!-- Numbered steps where ORDER matters --> <h2>How to Create an HTML File</h2> <ol> <li>Open VS Code</li> <li>Create a new file: <code>index.html</code></li> <li>Type the HTML skeleton</li> <li>Save the file (<kbd>Ctrl+S</kbd>)</li> <li>Open in Chrome (double-click the file)</li> </ol> <!-- Custom numbering --> <ol type="A"> <li>Section A: HTML Basics</li> <li>Section B: CSS Styling</li> <li>Section C: JavaScript</li> </ol> <!-- Start at a specific number --> <ol start="3"> <li>This is item 3</li> <li>This is item 4</li> </ol> </body>

Key Points

  • ol = ordered list — sequence matters.
  • Browser auto-numbers — don't write numbers yourself.
  • type='A/a/I/i' for letters or Roman numerals.
  • start='N' begins numbering at N.
18

List Items <li>

Q13

The <li> element represents a single item in a list. It must be a direct child of either <ul> or <ol> — it is invalid to use li outside a list. The li element is block-level and can contain any flow content: text, links, images, even nested ul or ol lists for sub-menus or outlines.

A common mistake is placing multiple items inside one li instead of using separate li elements, or placing non-li elements (like <p>) directly inside ul/ol. Both break valid HTML structure.

HTML
<body> <!-- Each item = one li --> <ul> <li>HTML</li> <li>CSS</li> <li>JavaScript</li> </ul> <!-- li can contain links, images, even nested lists --> <ul> <li> <a href="/html">HTML Guide</a> <ul> <li><a href="/html/tags">Core Tags</a></li> <li><a href="/html/forms">Forms</a></li> </ul> </li> <li><a href="/css">CSS Guide</a></li> </ul> <!-- Wrong — non-li elements directly in ul --> <!-- <ul><p>Item 1</p></ul> ← INVALID! --> </body>

Key Points

  • li = list item — must be inside ul or ol.
  • li can contain text, links, images, or nested lists.
  • One idea per li — don't put multiple items in one li.
  • Only li elements should be direct children of ul/ol.
19

Images: <img src>

Q14

The <img> element embeds images. It is a void element — no closing tag. The src (source) attribute is required and specifies the image location: either a relative path to a local file (photo.jpg, images/banner.png) or an absolute URL (https://example.com/logo.png).

File names are case-sensitive on web servers (Linux): Photo.jpg ≠ photo.jpg. Always use lowercase filenames without spaces (use hyphens: profile-photo.jpg). Setting width and height prevents layout shift while the image loads — the browser reserves the correct space before the image arrives.

HTML
<body> <!-- Local file — relative path --> <img src="photo.jpg" alt="Profile photo" width="300" height="300"> <!-- File in a subdirectory --> <img src="images/banner.png" alt="Course banner" width="800" height="200"> <!-- Image from the internet (absolute URL) --> <img src="https://picsum.photos/400/300" alt="Random placeholder" width="400" height="300"> <!-- figure + figcaption for labelled images --> <figure> <img src="diagram.png" alt="Block vs Inline diagram" width="600"> <figcaption>Figure 1: Block vs Inline element layout</figcaption> </figure> </body>

Key Points

  • src = image file path or URL (required).
  • Case-sensitive on servers: photo.jpg ≠ Photo.jpg.
  • No spaces in filenames — use hyphens.
  • Set width + height to prevent layout shift during load.
20

The alt Attribute

Q6, Q25

The alt attribute on <img> provides alternative text that: (1) displays if the image fails to load; (2) is read aloud by screen readers for visually impaired users; (3) is indexed by search engines (image SEO). A missing alt attribute is a WCAG Level A accessibility violation — the most serious level.

Write alt text that describes what the image shows, not what it is ("Photo of" and "Image of" are redundant — screen readers already announce "image"). For purely decorative images, use an empty alt (alt="") so screen readers skip them. For charts, describe the data trend, not just the chart type.

HTML
<body> <!-- Good: describes what the image shows --> <img src="profile.jpg" alt="Kim Jisoo smiling in front of Gachon University main building"> <!-- Decorative image: empty alt, screen reader skips it --> <img src="decorative-divider.png" alt=""> <!-- Chart: describe the DATA, not the chart type --> <img src="grades-chart.png" alt="Bar chart showing quiz scores: Week 1: 82, Week 2: 88, Week 3: 91"> <!-- BAD examples — avoid these --> <!-- <img src="photo.jpg"> missing alt --> <!-- <img src="photo.jpg" alt="photo"> not descriptive --> <!-- <img src="photo.jpg" alt="image of photo"> redundant --> </body>

Key Points

  • alt is required on every <img> — missing = accessibility violation.
  • Empty alt='' for decorative images only.
  • Describe WHAT the image shows — not 'photo of' or 'image of'.
  • Screen readers read alt text to visually impaired users.
21

The id Attribute

Q21 (part 1)

The id attribute gives an element a unique identifier. "Unique" is strict — no two elements on the same page can share the same id. It has three uses: (1) CSS targeting with the #id selector; (2) JavaScript access via document.getElementById('name'); (3) fragment links — <a href="#contact"> scrolls the page to the element with id="contact".

ID naming rules: start with a letter (not a number), no spaces, case-sensitive. By convention use kebab-case: main-header, contact-form.

HTML
<!DOCTYPE html> <html lang="en"> <head><meta charset="UTF-8"><title>ID Example</title></head> <body> <!-- Navigation using fragment links (# + id) --> <nav> <a href="#about">About</a> <a href="#skills">Skills</a> <a href="#contact">Contact</a> </nav> <section id="about"> <h2>About Me</h2> <p>Web programming student at Gachon.</p> </section> <section id="skills"> <h2>Skills</h2> </section> <section id="contact"> <h2>Contact</h2> </section> </body> </html>

Key Points

  • id must be unique — once per page.
  • CSS: #idName selector. JS: getElementById('idName').
  • Fragment links: <a href='#idName'> scrolls to that element.
  • Use kebab-case: main-header, contact-form.
22

The class Attribute

Q21 (part 2)

The class attribute assigns one or more reusable labels to an element. Unlike id, the same class can be applied to many elements, and one element can have multiple classes separated by spaces: class="card featured large". CSS targets classes with the dot selector (.className).

Classes are the primary tool for CSS styling: write a CSS rule for a class, then apply that class wherever you want the style. This creates consistent, maintainable design. In JavaScript, classes can be targeted with document.querySelectorAll('.className') and toggled dynamically with classList.add/remove/toggle.

HTML

Key Points

  • class is reusable — many elements can share a class.
  • Multiple classes: class='a b c' (space-separated).
  • CSS: .className. JS: querySelectorAll('.className').
  • Use class for styling; use id for unique JS targeting.

HTML Comments

Q22

HTML comments are written with <!-- comment text -->. Browsers completely ignore comments — they are never rendered on the page. Comments serve as: (1) notes explaining complex or non-obvious code; (2) section dividers in long HTML files; (3) temporary code disabling without deleting.

Warning: Comments ARE visible in the page source — anyone who presses Ctrl+U in Chrome can read them. Never put passwords, API keys, private business logic, or any sensitive data in HTML comments. Comments can span multiple lines.

HTML
<!DOCTYPE html> <html lang="en"> <head><meta charset="UTF-8"><title>Comments Example</title></head> <body> <!-- ═══ HEADER SECTION ═══════════════════════ --> <header> <h1>My Portfolio</h1> <!-- TODO: add logo image here later --> </header> <!-- ═══ MAIN CONTENT ═════════════════════════ --> <main> <p>Welcome to my page.</p> <!-- Temporarily disabled — will re-enable in Week 4 --> <!-- <section id="projects"> <h2>My Projects</h2> </section> --> </main> <!-- Never do this — visible in page source! --> <!-- password: mySecretPassword123 ← DANGEROUS! --> </body> </html>

Key Points

  • <!-- comment --> — browser ignores completely.
  • Visible in page source (Ctrl+U) — no secrets in comments.
  • Good for: section markers, explanations, disabling code.
  • Can span multiple lines inside <!-- ... -->.

Block vs Inline Summary

Q7, Q19

Every HTML element has a default display type — either block or inline. Block elements start on a new line, stretch to fill the full available width, and stack vertically. They can contain both block and inline elements. Examples: div, p, h1–h6, ul, ol, li, header, main, footer.

Inline elements flow within text, do not start a new line, and only take as much width as their content. They should only contain text or other inline elements. Examples: span, a, strong, em, img, input, label. The fundamental rule: you can nest inline elements inside block elements, but not block elements inside inline elements. CSS display property can override any element's default display type.

HTML
<body> <!-- BLOCK elements — each starts a new line --> <h2>Heading (block)</h2> <p>Paragraph (block)</p> <div>Div (block)</div> <!-- INLINE elements — flow on one line --> <p> This paragraph contains <strong>bold (inline)</strong>, <em>italic (inline)</em>, <a href="#">a link (inline)</a>, and <span style="color:teal">coloured text (inline)</span> — all on the same line. </p> <!-- CORRECT: inline inside block --> <p><strong>Good</strong> — span inside p</p> <!-- WRONG: block inside inline --> <!-- <span><p>Bad</p></span> ← INVALID! --> </body>

Key Points

  • Block: new line, full width, stacks vertically (div, p, h1).
  • Inline: flows with text, content-width only (span, a, strong).
  • Correct: inline inside block.
  • Wrong: block inside inline.
  • CSS display property can change any element's display type.
