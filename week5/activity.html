What is Fetch?

Beginner

Before fetch(), making HTTP requests required XMLHttpRequest — messy, verbose, and hard to read. fetch() was introduced in 2015 as the modern way to load data from a URL without reloading the page.

When you call fetch(url), JavaScript sends an HTTP request in the background. Your page stays alive and interactive. When the server responds, you process the data and update the DOM — all without a page refresh. This pattern powers every live feed, search autocomplete, and dashboard.

JavaScript
// fetch() makes an HTTP GET request to a URL
const response = await fetch('https://api.example.com/data');

// The response contains: status code, headers, body
console.log(response.status);  // 200
console.log(response.ok);      // true (status 200-299)

// Parse the body as JSON
const data = await response.json();
console.log(data); // plain JS object
Key concept: fetch() is asynchronous — it doesn't freeze your page while waiting for the server. The browser continues running other code (events, animations) while the request is in flight.
  • fetch() sends an HTTP request and returns a Promise
  • The page stays interactive while the request is in progress
  • By default, fetch() makes a GET request
  • The response body must be explicitly parsed with .json() or .text()

Basic fetch() Syntax

Beginner

The simplest fetch call takes a URL string and returns a Promise. You chain .then() callbacks to handle the response, and .catch() to handle errors.

JavaScript
// Three-step fetch pattern:
fetch('https://jsonplaceholder.typicode.com/posts/1')

  // Step 1: get the Response, parse the JSON body
  .then(response => response.json())

  // Step 2: use the parsed data
  .then(data => {
    console.log(data.title);  // "sunt aut facere..."
    document.querySelector('#output').textContent = data.title;
  })

  // Step 3: handle any error
  .catch(error => console.error('Error:', error));

Promises

Beginner

A Promise is an object representing a future value. It starts in the pending state, then either fulfills (with a value) or rejects (with an error).

fetch() returns a Promise that fulfills with a Response object when the server replies. You chain .then() to run code when it fulfills, and .catch() when it rejects.

JavaScript
// Creating a Promise manually (rare, but explains the concept)
const myPromise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve('Data loaded!');  // or reject(new Error('Failed'))
  }, 1000);
});

myPromise
  .then(value => console.log(value))   // 'Data loaded!'
  .catch(error => console.error(error));

// States: pending → fulfilled OR rejected
// fetch() handles creating the Promise for you
  • Pending: the async operation is in progress
  • Fulfilled: the operation succeeded — .then() runs
  • Rejected: the operation failed — .catch() runs
  • A Promise can only resolve ONCE — it won't call .then() twice

.then() Chaining

Beginner

Every .then() callback must return something — that return value becomes the input to the next .then(). This is how chains work: each step transforms and passes the data along.

JavaScript
fetch('https://jsonplaceholder.typicode.com/users/1')
  .then(res => {
    console.log('Status:', res.status);
    return res.json();  // MUST return — next .then() receives this
  })
  .then(user => {
    console.log('Name:', user.name);
    return user.email;   // pass just the email forward
  })
  .then(email => {
    console.log('Email:', email);
    document.querySelector('#contact').textContent = email;
  })
  .catch(err => console.error(err));
Common mistake: Forgetting return in a .then() callback. The next .then() receives undefined instead of your data, causing silent bugs.

Async / Await

Intermediate

async/await is syntactic sugar over Promises — same engine, cleaner syntax. Mark a function async, then put await before each Promise. The function pauses at each await until the Promise resolves, then continues — but the rest of your page keeps running normally.

JavaScript
// Same fetch — async/await style:
async function getPost(id) {
  const response = await fetch(`https://jsonplaceholder.typicode.com/posts/${id}`);
  const post = await response.json();
  return post;
}

// Call it
getPost(1).then(post => console.log(post.title));

// Or inside another async function:
async function init() {
  const post = await getPost(1);
  console.log(post.title);
}
Rule: You can ONLY use await inside an async function. Using it elsewhere causes a SyntaxError.
  • await pauses the function, not the page
  • Every async function automatically returns a Promise
  • Prefer async/await for new code — it's more readable
  • Use try/catch instead of .catch() with async/await

res.ok and Error Handling

Intermediate

Critical gotcha: fetch() only rejects (throws an error) when there is a network failure — no internet, DNS error, etc. A 404 or 500 from the server is still a fulfilled Promise! You must check response.ok yourself.

JavaScript
async function loadData(url) {
  try {
    const res = await fetch(url);

    // response.ok is true for status 200-299
    if (!res.ok) {
      throw new Error(`HTTP error: ${res.status}`);
    }

    const data = await res.json();
    return data;

  } catch (error) {
    // catches: network failure, !res.ok throw, JSON parse errors
    console.error('Failed:', error.message);
    throw error; // re-throw so caller knows it failed
  }
}
Never do this: const data = await fetch(url).then(r => r.json()) without checking res.ok — a 404 will give you an HTML error page parsed as JSON, causing a confusing crash later.

The Response Object

Intermediate

When fetch() resolves, you get a Response object with several useful properties and methods.

JavaScript
const res = await fetch(url);

// Properties
res.status;     // 200, 404, 500...  (HTTP status code)
res.ok;         // true if status 200-299
res.statusText; // "OK", "Not Found"...
res.headers;    // Headers object
res.url;        // the final URL (after redirects)

// Body reading methods (each returns a Promise, call once only)
const data   = await res.json();   // parse as JSON object
const text   = await res.text();   // raw string
const blob   = await res.blob();   // binary (images, files)

// Read a specific header
res.headers.get('content-type');  // 'application/json'
Body can only be read once. Calling .json() and then .text() on the same response throws an error — the stream is consumed.

URL Parameters

Intermediate

Most APIs accept parameters in the URL query string (e.g. ?id=1&limit=10). Build them safely using URLSearchParams — it handles encoding special characters automatically.

JavaScript
// Option 1: Template literal (simple, but no encoding)
const id = 42;
fetch(`/api/posts?userId=${id}&_limit=5`);

// Option 2: URLSearchParams (safe, handles special chars)
const params = new URLSearchParams({
  userId: id,
  _limit: 5,
  q: 'hello world'  // automatically encoded as hello+world
});
fetch(`/api/posts?${params}`);

// Result: /api/posts?userId=42&_limit=5&q=hello+world

Loading States

Intermediate

Good UX means showing a loading indicator while fetching. Use a finally block to hide the spinner — it runs whether the fetch succeeded or failed.

JavaScript
async function loadWithSpinner() {
  const spinner = document.getElementById('spinner');
  const content = document.getElementById('content');

  spinner.style.display = 'block';  // show spinner
  content.textContent = '';

  try {
    const res  = await fetch('https://jsonplaceholder.typicode.com/posts/1');
    if (!res.ok) throw new Error('HTTP ' + res.status);
    const data = await res.json();
    content.textContent = data.title;
  } catch (err) {
    content.textContent = 'Error: ' + err.message;
  } finally {
    spinner.style.display = 'none';  // ALWAYS hide spinner
  }
}
  • finally runs after try OR catch — perfect for cleanup
  • Show loading state BEFORE the await, hide AFTER in finally
  • Disable buttons during fetch to prevent duplicate requests

POST Requests

Advanced

To send data (create, update), use a POST request with a method, headers, and body in the options object. The body must be a string, so use JSON.stringify() for objects.

JavaScript
async function createPost(title, body) {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',  // tell server what we're sending
    },
    body: JSON.stringify({ title, body, userId: 1 }),
  });

  if (!res.ok) throw new Error('POST failed: ' + res.status);
  const newPost = await res.json();
  console.log('Created:', newPost.id);  // server returns new resource
  return newPost;
}

Real API Demo

Intermediate

Let's fetch from a real public API — the Official Joke API — and display the result dynamically in the DOM.

JavaScript
async function fetchJoke() {
  const setup = document.getElementById('setup');
  const punchline = document.getElementById('punchline');
  setup.textContent = 'Loading...';
  punchline.textContent = '';
  try {
    const res = await fetch('https://official-joke-api.appspot.com/random_joke');
    if (!res.ok) throw new Error('Status ' + res.status);
    const joke = await res.json();
    setup.textContent = joke.setup;
    punchline.textContent = joke.punchline;
  } catch (err) {
    setup.textContent = 'Error: ' + err.message;
  }
}

Error Patterns

Advanced

In production, handle errors gracefully — show the user something useful, not a blank screen or a JavaScript error.

JavaScript
async function robustFetch(url) {
  let data = null;
  let error = null;
  let loading = true;

  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error(`${res.status} ${res.statusText}`);
    data = await res.json();
  } catch (e) {
    // Distinguish network error vs HTTP error:
    error = e.message.startsWith('Failed to fetch')
      ? 'No internet connection'
      : `Server error: ${e.message}`;
  } finally {
    loading = false;
  }

  return { data, error, loading };
}

// Usage
const { data, error } = await robustFetch('/api/posts');
if (error) showErrorBanner(error);
else renderPosts(data);

Exercise 2 — User Profile Card

Intermediate

Goal: Fetch a user by ID from JSONPlaceholder and display their name, email, and city in a styled card. Include a number input so the user can pick user ID 1-10.

API: https://jsonplaceholder.typicode.com/users/{id} — Returns user object with name, email, address.city, company.name
Live Editor
async function fetchUser() {
  const id = document.getElementById('uid').value;
  const card = document.getElementById('card');
  card.innerHTML = 'Loading...';
  try {
    const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    if (!res.ok) throw new Error('User not found');
    const u = await res.json();
    card.innerHTML = `
      <div class="card">
        <h3>${u.name}</h3>
        <p>📧 ${u.email}</p>
        <p>📍 ${u.address.city}</p>
        <p>🏢 ${u.company.name}</p>
      </div>`;
  } catch(err) { card.innerHTML = '<p style="color:red">' + err.message + '</p>'; }
}

Exercise 3 — Fetch + DOM List

Intermediate

Goal: Fetch 5 posts from JSONPlaceholder and render them as a list with title and body. Add a "Load More" button that fetches the next 5.

API: https://jsonplaceholder.typicode.com/posts?_start=0&_limit=5
Live Editor
let start = 0;
async function loadMore() {
  const list = document.getElementById('list');
  const btn = document.getElementById('more-btn');
  btn.textContent = 'Loading...'; btn.disabled = true;
  try {
    const res = await fetch(
      `https://jsonplaceholder.typicode.com/posts?_start=${start}&_limit=5`
    );
    if (!res.ok) throw new Error('HTTP ' + res.status);
    const posts = await res.json();
    posts.forEach(p => {
      list.innerHTML += `<div class="post"><h4>${p.title}</h4><p>${p.body.slice(0,80)}...</p></div>`;
    });
    start += 5;
  } catch(err) { list.innerHTML += `<p style="color:red">${err.message}</p>`; }
  finally { btn.textContent = 'Load More'; btn.disabled = false; }
}

Exercise 4 — POST Request

Advanced

Goal: Build a form that collects a title and body, then POSTs to JSONPlaceholder. Show the server's response (the new post with its assigned ID).

API: POST to https://jsonplaceholder.typicode.com/posts — Body: {"title":"...", "body":"...", "userId":1} — Returns: the new post with id
Live Editor
async function submitPost() {
  const title = document.getElementById('title').value;
  const body  = document.getElementById('body').value;
  const result = document.getElementById('result');
  result.textContent = 'Submitting...';
  try {
    const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ title, body, userId: 1 }),
    });
    if (!res.ok) throw new Error('HTTP ' + res.status);
    const post = await res.json();
    result.textContent = JSON.stringify(post, null, 2);
  } catch(err) { result.textContent = 'Error: ' + err.message; }
}
